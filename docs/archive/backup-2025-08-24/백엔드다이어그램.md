### 투표 완료 처리 최적화
- **병렬 처리**: 데이터 조회 및 업데이트 동시 실행
- **배치 처리**: Firestore 500개 제한 준수
- **스로틀링**: 실시간 부하 분산
- **자동 재시도**: 실패 시 재시도 로직

## 8. 데이터베이스 컬렉션 구조

### 핵심 컬렉션 (35개)

#### 사용자 관리
- `users`: 사용자 프로필, 포인트, 설정
- `characters`: 사용자 아바타/캐릭터
- `settings`: 개인 설정
- `notifications`: 알림 관리

#### 콘텐츠 관리
- `posts`: A vs B 포스트 메인 데이터
- `comments`: 댓글 시스템
- `images`: 이미지 메타데이터
- `video`: 비디오 메타데이터
- `encodings`: 비디오 인코딩 상태

#### 소셜 기능
- `likes` / `dislikes`: 좋아요/싫어요
- `chats` / `group_chats`: 메시징
- `messages` / `group_messages`: 메시지 내용
- `friends_list`: 친구 관계

#### 게임화 요소
- `rankings`: 리더보드
- `point`: 포인트 거래 내역
- `votes` / `votecounts`: 투표 시스템
- `premium_users`: 프리미엄 구독

#### 검색 및 카테고리
- `searches`: 검색 기록
- `interest`: 관심사 카테고리
- `jops_category` / `jops_name`: 직업 분류

#### 콘텐츠 모더레이션
- `image_moderation`: 이미지 검열 결과
- `content_validations`: AI 검증 로그 (Functions에서 생성)

## 7. 3-Layer 캐싱 시스템 아키텍처

### 캐싱 레이어 플로우

```mermaid
sequenceDiagram
    participant U as 사용자
    participant A as Flutter App
    participant L1 as Memory Cache<br/>(SimpleMemoryCache)
    participant L2 as Local DB<br/>(Hive)
    participant L3 as Offline Cache<br/>(Firestore)
    participant N as Network<br/>(Firebase Server)
    participant S as Statistics<br/>(CacheStatistics)
    
    U->>A: 데이터 요청
    A->>L1: 메모리 캐시 확인
    
    alt L1 캐시 히트
        L1->>A: 즉시 반환 (<10ms)
        A->>S: L1 히트 기록
        A->>U: 데이터 표시
    else L1 캐시 미스
        A->>L2: Hive DB 확인
        
        alt L2 캐시 히트
            L2->>A: 데이터 반환 (10-30ms)
            A->>L1: 메모리 캐시 업데이트
            A->>S: L2 히트 기록
            A->>U: 데이터 표시
        else L2 캐시 미스
            A->>L3: Firestore 오프라인 캐시 확인
            
            alt L3 캐시 히트
                L3->>A: 데이터 반환 (50-100ms)
                A->>L1: 메모리 캐시 업데이트
                A->>L2: Hive DB 업데이트
                A->>S: L3 히트 기록
                A->>U: 데이터 표시
            else L3 캐시 미스
                A->>N: 네트워크 요청
                N->>A: 서버 데이터 (300-500ms)
                
                par 병렬 캐시 업데이트
                    A->>L1: 메모리 캐시 저장
                    A->>L2: Hive DB 저장
                    A->>L3: Firestore 캐시 저장
                end
                
                A->>S: 네트워크 히트 기록
                A->>U: 데이터 표시
            end
        end
    end
    
    Note over L1: TTL: 5분<br/>최대 100개 항목<br/>LRU 정책
    Note over L2: 영구 저장<br/>JSON 직렬화<br/>무제한
    Note over L3: 자동 동기화<br/>무제한 크기<br/>오프라인 지원
```
